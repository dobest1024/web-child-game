## 2. 总体要求

1. **不引入任何依赖和构建步骤**。还是普通 `<script>`，`file://` 直接打开能玩。
2. **代码风格和现有代码一致**：`'use strict'`、2 空格缩进、单引号、短函数、中文注释（注释不多，只写"为什么"）。
3. **数据驱动**：关卡、敌人、Boss、道具都写成数据表，逻辑里尽量不写死某一关的特殊判断。
4. **老存档不能坏**。改存档结构时同时改 `defaultSave` 和 `fillSave`，并写迁移。
5. 每个里程碑做完，游戏都应该是**能完整玩的**状态（没做到的世界先锁着）。
6. 所有界面文字是简体中文，标题页和通关页保留"作者：周逸卿"。

## 3. 关卡数据格式

实际实现里，关卡写成一张文本表 `LEVEL_TABLE`（每行 `关号|名字|类型|玩法|Boss|敌人|同屏|D|标记`），由 `parseLevelRow` 解析。下面是早先规划的对象写法，含义一样：

```js
'use strict';
// ===== 100 关（数据来自 docs/02-100关设计.md 第 8 节）=====
// type: normal / mini / big / final
// mode: kill / collect / survive / push / rescue / gold
// enemies: 'g6o3' 这种写法；'∞goh' 表示不限数量，从这几种里抽
const LEVEL_SPECS = [
  { n: 1, name: '你好坦克', type: 'normal', mode: 'kill', enemies: 'g8', maxOn: 3, D: 1, flags: { quietStart: 3 } },
  { n: 3, name: '铁锤将军', type: 'mini', mode: 'kill', boss: ['hammer'], enemies: 'g4o1', maxOn: 3, D: 2 },
  { n: 4, name: '星星草原', type: 'normal', mode: 'collect', goal: 6, enemies: 'g6o3h1', maxOn: 3, D: 2 },
  { n: 7, name: '坚持住！', type: 'normal', mode: 'survive', goal: 60, enemies: '∞goh', maxOn: 3, D: 3 },
  { n: 9, name: '捣蛋双胞胎', type: 'mini', mode: 'kill', boss: ['hammer', 'shotgun'], enemies: 'g3o3', maxOn: 3, D: 4 },
  { n: 17, name: '雪地金宝宝', type: 'normal', mode: 'gold', goal: 5, golds: 8, enemies: 'g6b2', maxOn: 3, D: 3 },
  { n: 56, name: '萤火虫之夜', type: 'normal', mode: 'kill', night: true, enemies: 'g6o4n2', maxOn: 4, D: 6 },
  { n: 83, name: '陨石雨', type: 'normal', mode: 'kill', meteor: true, enemies: 'g4o4u3l3k3', maxOn: 5, D: 7 },
  // ……共 100 条
];
```

然后由 `LEVEL_SPECS` 生成 `LEVELS`（替换 `data.js` 末尾现有的 20 关循环）：

```js
const LEVELS = LEVEL_SPECS.map(s => {
  const li = s.n - 1, world = Math.floor(li / 10);
  return {
    ...s, li, world, theme: WORLDS[world].theme,
    boss: s.boss ? s.boss[0] : null, bosses: s.boss || null,
    map: genMap(li, s),              // genMap 改成读 spec 里的 type / mode / 世界配方
    enemies: expandEnemies(s.enemies, li),
  };
});
```

- `BOSS_AT` 不再需要，Boss 从 spec 读。
- `genMap` 里所有 `Math.floor(li / 5)` 的"世界"算法都要改成 `Math.floor(li / 10)`。
- 地图种子保持 `20261017 + li * 977` 的写法，这样同一关每次都一样。
- 写一个开发用的自检函数 `checkLevels()`（只在 `?dev=1` 时运行）：检查 100 关都连通、玩法物件都能开到、敌人没有早于介绍关出现、Boss 键都存在。

## 5. 存档迁移细则

```js
// fillSave 里
if (!s.ver || s.ver < 3) {
  // stars[0..19] 原样保留，对应新的第 1–20 关
  // ach.final 已经有的保留（老版本第 20 关是魔王机甲）
  s.ver = 3;
}
s.skipped = Array.isArray(s.skipped) ? s.skipped.slice(0, LEVELS.length).map(Boolean) : [];
s.trophies = obj(s.trophies);   // { snailHat: 时间戳, ... }
s.seen = obj(s.seen);           // { enemies: { d: 1 }, pups: { magnet: 1 } }
s.bossKills = obj(s.bossKills); // { snail: 次数 }
s.tanks = [num(s.tanks[0], 0, PLAYER_TANKS.length - 1, 0), num(s.tanks[1], 0, PLAYER_TANKS.length - 1, 1)];
```

- `obj()` 只保留键名是白名单里的、值是数字的项。
- 没解锁的坦克（橙橙、粉粉）读档时换回默认坦克。
- 存档键名继续用 `tanke-save-v2`，不要改，否则老玩家的进度会丢。

## 6. 测试

### 6.1 手动
- `?unlock=1` 解锁全部关卡（已有）；`?dev=1` 开自检和测试小地图（M0、M3 里新做）。
- `window.__tk`（已有）暴露 `G`（当前对局）、`startLevel`、`LEVELS`、`save`、`Editor`、`Meta`，可以在控制台直接改状态。

### 6.2 自动

已经跑过的结果（2026-10-18，用一个会寻路、会瞄准的机器人，不开无敌）：宝宝难度赢 98 关、小勇士 86 关、大英雄 53 关、双人小勇士 98 关；开无敌时 100 关全部能打完（推箱、收集、营救都能完成），没有报错。机器人比孩子准得多，实际用时会比下面的数字长。

推荐做法（Playwright 跑浏览器，或者像上面一样在 Node 里只加载逻辑脚本、给 `document` 等打桩）：
写一个测试页或脚本，对每一关：
1. 用 `buildGame(LEVELS[i], { tanks: [0], diff: 0 })` 建局。
2. 用一个简单的机器人控制玩家（朝最近的敌人转向并开火，躲开正在预警的区域），把 `updateGame(dt)` 快进跑，最多 6 分钟游戏时间。
3. 记录：有没有报错、赢 / 输 / 超时、用时、剩余血量。

**目标**：
- 100 关都没有报错。
- 宝宝难度下机器人能赢 ≥ 90 关；输掉或超时的关，人工看一下是不是设计问题。
- 普通关用时 1.5–4 分钟，Boss 关 1.5–5 分钟。
- 2 人模式抽查每个世界 2 关。

### 6.3 回归
每个里程碑结束时，第 1–20 关、新手教学、自制关卡都要跑一遍，确认没坏。
